# 开发提示词 #281–#284:位置跟随 —— 用户换了城市,首页得跟上

来源是一句反馈:「开放的城市貌似在三端里面没有,我默认是开放中国所有的城市;
用户进来后若不在原来位置,则重新自动定位到当前的位置」。

先调研再动手,调研的结论**推翻了问题的前半句**:开城和城市选择器都在,
真正缺的是**首页的位置跟随**。

---

## 1. 调研结论:三件事和直觉不一样

### 1.1 全国已经是开放的,不需要改

`platform_flags.open_cities` 生产上是 **空 = 不限制**
(`services/flags.py:open_cities()` 返回 None 即不限制)。
`open_cities` 只在一处生效:商家点「开始营业」时,清单外的城市拦下来
(`merchants.py:509`,可入驻待审、不可营业)。**对用户端没有任何限制。**

### 1.2 用户端根本不按「城市」找店,按距离找

`GET /merchants` 收的是 `lat/lng + radius`,SQL 按距离排。
「开了哪个城市」对用户是**无感的** —— 他看到的是「附近有没有店」。
所以「把开放城市列给用户看」这件事,本身价值不大。

### 1.3 城市选择器早就有,只是用在别处

`packages/shared/lib/src/city_picker.dart` 的 `CityPref` / `CityPicker`
**已经在地址搜索页用着**(`address_pages.dart:308`)—— 它解决的是另一个
真问题:腾讯 POI 搜索 `region_fix=1` 把结果限死在指定城市,城市选错就
一条都搜不到(实测西安的小区在 `city=成都` 时返回 0 条)。

所以「三端没有城市」这个说法不成立。缺的是下面这个。

---

## 2. 真正的问题:首页的位置不跟随

`main.dart` 的 `_load()`(693 行起):

```dart
final address = widget.deliveryAddress;
if (address != null) {
  _myLat = address.lat; _myLng = address.lng;   // ← 用收货地址,不管人在哪
} else {
  final location = await resolveMyLocation(context);  // ← 只在这时定位
}
```

由此三个缺口:

| # | 缺口 | 现在会发生什么 |
|---|---|---|
| ① | **选过收货地址后就锁死** | 在西安选了「家」,出差到北京打开 App,首页还是西安的店 |
| ② | **从后台恢复不重新定位** | `MerchantListView` 没有 `WidgetsBindingObserver`(全 App 只有订单详情/地图/拼单页有)。飞机落地、App 一直在后台,切回来还是起飞前那个位置 |
| ③ | **定位失败降级到演示城市** | `_load()` 里 `list.isEmpty && _realLocation` 时跳成都(`demoLat/demoLng`)。这是**给应用商店审核员**的兜底(审核人员在外地/海外),真实运营时西安用户会看到成都的店 |

---

## 3. 方案

### 判据先定死:**不静默改用户选的地址**

用户选「送到西安的家」很可能是**故意的** —— 人在北京出差,给家里老人点单
是最常见的场景之一。App 因为「你人在北京」就把地址偷偷改成北京,
他不看第二眼就会把饭点到自己出差的酒店。

**所以位置跟随只能是「检测 + 提示 + 他点了才换」,不能是自动切换。**
这条和仓库里那句「让用户误以为某件事在生效,比没有这个功能更坏」是同一条:
静默改地址比不改更糟。

### #281 首页监听生命周期,回到前台重取定位

- `_MerchantListViewState` 加 `WidgetsBindingObserver`,`resumed` 时
  **只重取定位、不重拉列表**(拉列表交给下一条判断);
- 取定位要轻:`Geolocator.getLastKnownPosition()` 优先,拿不到再
  `getCurrentPosition`(低精度即可,我们只需要判断「是不是换城市了」);
- ⚠️ 频率要压:`resumed` 会因为切个通知栏、接个电话反复触发。
  加个最小间隔(建议 5 分钟)。

### #282 跨城才提示,同城跨区不提示

- 比较「当前定位」与「首页正在用的位置」(收货地址或上次定位)的直线距离;
- **阈值 30km**:同城跨区(公司→家)不提示,跨城才提示。
  用距离不用城市名 —— 城市名要逆地理多一次请求,而且直辖市/省直管县的
  名字口径很乱;
- 超过阈值时,在列表顶部出一条**非阻断**提示条(不是弹窗,不挡操作):
  「你现在好像在<当前城市>,正在按 <地址简称> 找店 [切到当前位置] [不用]」
  - 「切到当前位置」→ 清掉 `deliveryAddress`,回到实时定位模式;
  - 「不用」→ **本次会话不再提示**(存内存即可,重启 App 重新判断);
- 城市名只在这条提示里要,调 `geo_city` 逆地理一次,失败就退化成
  「你现在好像不在 <地址简称> 附近」——**不因为拿不到城市名就不提示**。

### #283 定位失败的兜底改成让他选城市,别直接跳成都

现在的降级链是「定位失败 → 演示城市(成都)」,理由是应用商店审核兜底,
那个理由**仍然成立**,但顺序错了:

1. 定位拿不到 / 附近没店 → **先让用户选城市**(复用已有的 `CityPicker`,
   数据来自 `GET /geo/cities`,那接口返回的是「实际有商家的城市」);
2. 用户选了 → 按该城市中心坐标找店;
3. 用户不选、直接退出选择 → **才**降级演示城市,并保留现有的
   「正在展示演示城市商家」提示条。

这样审核兜底一条不少,而真实用户不会莫名其妙看到外地的店。

### #284 顶部地址栏把「当前位置」换成真实地名

现在没选地址时顶部固定显示「当前位置」四个字 —— 用户没法判断 App 到底
定到哪了。定位成功后逆地理拿到区级地名填上去(「雁塔区」),
定位失败就显示「定位失败,点这里选城市」。

一眼能看出定位对不对,是上面三条的前提 —— 否则用户连「App 认为我在哪」
都不知道,更不会去点那个切换提示。

---

## 4. 明确不做

- **不做「开放城市」列表页**:用户端按距离找店,城市对他无感;
  真要看「哪些城市有店」,官网已经有(`web/src/CityGrid.jsx`);
- **不自动改收货地址**(判据在上面);
- **不做 IP 定位兜底**:`witness/README` 那句「不收集、不上传关于你的
  任何信息」是全平台口径,定位只用系统权限给的那份;
- **不因为跨城就拦下单**:用户就是想给异地点单的话,那是他的自由 ——
  配送范围本来就由商家的 `delivery_max_km` 兜着,超出范围下不了单,
  不需要在城市这一层再拦一次。

## 5. 顺序与规模

```
#284 顶部显示真实地名   ← 最小,2 小时,而且是其余几条的前提
#281 生命周期重取定位   ← 半天
#282 跨城提示条        ← 半天,判据(30km/非阻断/本次不再提示)已定
#283 定位失败选城市     ← 半天,组件是现成的
```

## 6. 验收

- 模拟位置从西安改到北京 → 切后台再回来 → 提示条出现,点「切到当前位置」
  后列表变成北京的店;点「不用」后本次会话不再提示;
- 同城跨区(雁塔 → 未央)→ **不出提示**;
- 关掉定位权限 → 出城市选择,选西安 → 看到西安的店;直接退出 → 才看到
  演示城市 + 现有的那条提示;
- 顶部地址栏:定位成功显示区名,失败显示「定位失败,点这里选城市」。
