# 超级赞小程序开发者文档

超级赞小程序就是**普通网页**:HTML、CSS、JavaScript,打成 zip 上传,平台托管、审核、发布;
用户在超级赞 App 里下拉就能打开。技术路线对标 Telegram Mini Apps —— 如果你写过 TG 的 Mini App,
这里几乎可以照搬(见[从 Telegram 迁移](telegram.md))。

## 为什么是普通 Web 技术

- 不用学新框架、不用装开发工具。React、Vue、原生 JS 都行,只要最后是静态文件;
- 同一份代码在安卓、iOS、网页版上都能跑;
- 平台托管每个版本的**原始字节**,详情页公示 SHA-256,任何人都能拿你开源的构建产物来对。

## 平台对你、对用户的承诺

这些是写进代码、有测试守着的规则,不是宣传语:

| 承诺 | 具体是什么 |
|---|---|
| 登录凭据永远不进网页 | 页面拿不到用户的登录 token;要知道「这是谁」只有 [initData](concepts.md#initdata) 一条路,由平台签名、你的后端验签 |
| 用户在每个应用里是不同的人 | 你拿到的是**只在你的应用里有效**的 `open_id`,拿不到手机号、平台账号 id,也没法和别的应用串联 |
| 不卖位置 | 目录排序是公开的纯函数:精选在前(人工、理由公示),其余按首次上架时间。没有竞价、没有付费推荐。见[运营规范](operations.md) |
| 审核看的就是上线的那一份 | 每个版本的文件只写一次,不能事后替换 |
| 处罚有理由、能申诉 | 每个结论都带[原因代码](review.md#原因代码)和说明;7 天内可以申诉一次,**换一名审核员**复核 |
| 本期没有支付和广告 | 小程序里不能收钱、不能放广告,小游戏只上免费单机 |
| 用户掌控自己的数据 | 用户能看、导出、清空自己在你的应用里存的数据;你的服务端不能直读 |
| 敏感能力逐次授权 | 昵称头像要用户同意;定位、扫码等以后开放时每次都要确认 |

## 能做与不能做

**能做**:工具、效率、生活服务、学习、休闲小游戏;连你自己的后端(在后台声明服务器域名);
存用户数据到[云存储](storage.md)(每人 5 MB);用原生的主按钮、返回键、弹窗、触感、系统分享。

**本期不能做**:支付和内购、广告、定位 / 扫码 / 剪贴板 / 手机号(M3 再开放)、在容器里打开别家网页
(外链一律先问用户、交系统浏览器)、服务端渲染(托管的只能是静态文件)。

## 费用

发布免费。没有年费、认证费、流量费,也没有可以花钱买的曝光。
