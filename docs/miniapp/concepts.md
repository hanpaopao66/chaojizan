# 核心概念

## AppID 与 AppSecret

- **AppID**:`sz` + 16 位小写十六进制,如 `sz8f3a2c1b9d4e7f06`。公开的,也是托管子域名。
- **AppSecret**:32 字节随机数的 base64url(43 个字符)。**只在创建和轮换时显示一次**;
  平台只存密文,日志里永远不出现。它只用来验 initData 的 `hash`,不要放进网页。

## open_id

用户在**你的应用里**的身份:`o_` + 26 位 base32。

- 同一个用户在你的应用里永远是同一个 `open_id`;在不同应用里一定不同;
- 它是随机生成、表映射的,**不是**从用户 id 算出来的 —— 推不回用户是谁,也没法和别的应用对上;
- 你拿不到手机号和平台账号 id。要昵称头像得申请 `profile` 能力、用户同意(见 [SDK · requestProfile](sdk-reference.md#requestprofile))。

## initData

启动时平台签发的一段 querystring,告诉你的后端「这确实是超级赞 App 里的这个 open_id」:

```text
app_id=sz0123456789abcdef&auth_date=1790000000&launch_id=…&sig_kid=56475aa7
&start_param=note42&user=%7B%22language_code%22%3A%22zh-CN%22%2C%22open_id%22%3A%22o_…%22%7D
&hash=797f…&signature=Yd_T…
```

| 字段 | 说明 |
|---|---|
| `app_id` | AppID |
| `auth_date` | 签发时间(unix 秒) |
| `launch_id` | 这次启动的随机串,你的后端可以用它防重放 |
| `user` | JSON:`open_id`、`language_code`;用户同意过 requestProfile 的应用多 `nickname`、`avatar_url` |
| `start_param` | 直达链接带来的参数(可无) |
| `env` | 模拟器启动时是 `sim`(可无)—— **你的后端应据此区分测试流量** |
| `sig_kid` | 签名用的平台公钥 id |
| `hash` | 用 AppSecret 算的 HMAC |
| `signature` | 平台 Ed25519 签名 |

页面里 `SuperZ.WebApp.initData` 是原串,**原样交给你的后端验签**;`initDataUnsafe` 是解析好的对象,只用来展示。
验签的两种方法、测试向量见[服务端](server.md)。

## 托管

你上传 zip,平台存成**不可变**的版本:每个文件只写一次,审核看的、用户打开的、详情页公示 SHA-256 的是同一份字节。

- 线上地址:`https://<AppID>.<托管域名>/v/<版本号>/index.html`,每个应用一个子域名,互相隔离;
- 平台按应用生成 CSP:脚本只能同源,网络请求只能去你声明的服务器域名,相机、麦克风、定位被 Permissions-Policy 堵住
  (敏感能力只能走桥,有确认、有记录);
- SDK 在每个托管子域名下都有一份:`/_sdk/2/sz-webapp.js`(最新 2.x)和 `/_sdk/2.0.0/sz-webapp.js`(不可变)。

## 版本

| 状态 | 意思 |
|---|---|
| 已上传 | 开发版,只在模拟器和体验版里能打开 |
| 体验版 | 体验者扫码能打开(同一时刻一个) |
| 审核中 | 已提交;可以撤回 |
| 审核通过 | 可以发布(或打开自动发布) |
| 已驳回 | 带原因代码;改好了重新上传一个版本 |
| 当前版本 | 用户打开的就是它 |
| 历史版本 | 被新版本替下来的,可以回滚过去 |

## 能力与授权

- **基础能力**(所有应用都有):initData、云存储、分享、触感、弹窗、打开外链;
- **小游戏**额外有:全屏、锁方向;
- **要申请**的:`profile`(昵称和头像)。审核通过后,用户第一次调用时宿主弹确认,用户可以在设置里撤回;
- 定位、扫码、剪贴板、手机号(仅企业)是下一阶段的事,现在申请会回「暂未开放」。

宿主**每次调用都当场查能力**,不是打开时查一次 —— 平台收回能力,下一次调用就回 `4001`。

## 配额与限流

| 项 | 限额 |
|---|---|
| 每个开发者的应用数 | 个人 5 个、企业 50 个 |
| 每个应用的体验者 | 20 人 |
| 上传版本 | 每个应用每小时 30 次 |
| 启动(换 initData) | 每个用户每分钟 30 次 |
| 云存储 | 每个(应用, 用户)1024 个键、5 MB;每分钟 120 次调用 |
| 用户投诉 | 每人每天 10 次 |
| 修改服务器域名 | 每个应用每月 50 次,改完只对新启动生效 |

这些数字和[开发者规则](/developers/rules)是同一处代码常量生成的。
