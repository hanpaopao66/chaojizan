# 用 AI 助手发布

把开发者账号接进 AI 助手(Claude,以及任何支持 MCP 的客户端),然后用一句话传包、提审、发布:

> 把 ./dist 作为 1.2.0 传到《方块消消》,更新说明写「修了存档丢失」,提交审核;审核过了就发布上线。

它背后调的是开发者后台同一套接口,只是替你点按钮。**审核还是平台的人做** —— 助手能替你提审,不能替你过审。

## 能做什么、不能做什么

| 能做 | 做不到 |
|---|---|
| 建小程序、建小游戏,改名称、介绍、分类、图标、隐私政策 | 下架、删除应用 |
| 传包(zip,或者构建好的文件夹,它来打包),看校验报告 | 改 AppSecret、改请求域名 |
| 设体验版、提交审核、撤回审核 | 加减体验者(那是别人的手机号) |
| **审核通过的版本**发布上线、回滚到之前发布过的版本 | 让没过审的版本上线 |
| 看审核结论、驳回原因、平台通知、数据 | 实名 / 企业认证、签开发者规则、申诉 |

右边这一列要么删了回不来,要么是你本人的判断和身份,留给你自己在[开发者后台](/dev/)里做。
这条线划在服务端:助手令牌只放行「发布小程序和小游戏」那一张白名单,其余一律 403。

## 接上

**1. 签令牌。** 开发者后台[账号](/dev/)→「AI 助手」→ 签发。明文只显示这一次,马上复制。
开发者账号签的令牌只有「发布小程序和小游戏」这一项权限。

**2. 下载 MCP 服务。** 只有一个文件,只用 Python 标准库(3.9 以上),不用装依赖:

```bash
curl -O https://raw.githubusercontent.com/hanpaopao66/chaojizan/main/mcp-server/server.py
```

**3. 接进客户端。** 以 Claude Code 为例:

```bash
claude mcp add superz -e SUPERZ_API=https://chaojizan.cc -e SUPERZ_AGENT_TOKEN=刚才那串 -- python3 /绝对路径/server.py
```

Claude 桌面版、Cursor 等客户端的配置写法见 [MCP 服务说明](https://github.com/hanpaopao66/chaojizan/blob/main/mcp-server/README.md)。

**4. 干跑一次。** 它把能用的只读工具各打一遍,不会建应用、不会传包:

```bash
SUPERZ_API=https://chaojizan.cc SUPERZ_AGENT_TOKEN=刚才那串 python3 server.py --selftest
```

## 一次完整的发布

| 你说 | 助手调的工具 |
|---|---|
| 「我的开发者账号能提审吗?」 | `get_developer_account`:认证了没有、规则签了没有 |
| 「建一个小游戏,叫《方块消消》,分类休闲益智」 | `create_miniapp` |
| 「介绍写……,隐私政策写……」 | `update_miniapp_listing` |
| 「把 ./dist 作为 1.0.0 传上去,设成体验版」 | `upload_miniapp_version` → `set_trial_version` |
| 「提交审核,给审核员的备注:打开即玩,不用登录」 | `submit_miniapp_review` |
| 「审核结果出来了吗?被驳回的话原因是什么」 | `list_developer_messages`、`get_review_decisions` |
| 「过了就发布上线」 | `release_miniapp_version` |
| 「线上这版有问题,回滚到 1.0.0」 | `rollback_miniapp` |

提交审核之前,账号要已经认证、签过开发者规则(见[快速开始](quickstart.md));审核看什么见[审核规范](review.md)。

## 给文件夹时怎么打包

- 给**构建产物**那个文件夹,不是源码目录。根目录要有 `index.html` 和 `superz.json`,
  和手动上传的包是同一个格式(见[快速开始](quickstart.md))。
- 只装小程序包允许的扩展名(html、js、css、json、图片、字体、音视频、wasm 等);
  `.env`、`.git` 这类点开头的文件和目录、`node_modules`、符号链接一律跳过,跳过了什么会原样告诉你。
  你电脑上的密钥、配置因此进不了包。
- 打包后超过 30MB 不传。平台收到后照常逐条校验,没过会把校验报告带回来,按报告改完重传就行。

## 令牌的安全

- 只有「发布小程序和小游戏」这一项:它下不了单、发不了视频、读不到任何用户数据。
- 丢了就去[开发者后台](/dev/)吊销,下一次调用就是 401;同一页能看到这个助手做过的每一次调用。
- 大多数客户端在调用工具前会让你确认一次。**提交审核、发布上线这两步,确认前看一眼 AppID 和版本号。**

## 常见问题

**助手说「这个令牌没有发布小程序的权限」。** 你用的是用户端 App 签的令牌(那里只能勾点餐、发视频)。
去开发者后台签一个。

**提交审核被拒,说没认证或没签规则。** 这两件要你本人在开发者后台做,助手做不了。

**发布上线失败。** 只有审核通过的版本能发布。先问助手这个版本的状态,被驳回的话看驳回原因。

**包没通过校验。** 报告里每一条都写着哪个文件、什么问题。常见的是缺 `superz.json`、
带了不允许的扩展名、单个文件超过 5MB。
