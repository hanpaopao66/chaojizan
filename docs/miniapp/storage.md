# 云存储(CloudStorage)

给每个用户在你的应用里一块小地方存数据,不用自己搭后端。官方记事本和 2048 就只用它。

## 模型

- **作用域是(应用, 用户)**:A 应用永远读不到 B 应用的数据;同一个应用里,甲读不到乙的;
- **你的服务端不能直读**:只有用户在你的应用里打开时,页面经宿主读写。要在服务端处理的数据,请存到你自己的后端;
- 键 `^[A-Za-z0-9_.:-]{1,128}$`;值是字符串(对象先 `JSON.stringify`),UTF-8 ≤ 65,536 字节;
- 每个键带一个单调递增的版本号 `rev`。

## 配额

| 项 | 上限 |
|---|---|
| 键数 | 每个(应用, 用户)1024 个 |
| 总量 | 每个(应用, 用户)5 MB(键名 + 值的 UTF-8 字节) |
| 单次批量 | 100 个键 |
| 调用频率 | 每个(应用, 用户)每分钟 120 次(批量算一次) |

恰好到上限能写,多一个字节回 `4006`;频率超了回 `4005`。

## 读写

```js
const cs = SuperZ.WebApp.CloudStorage
await cs.setItem('settings', JSON.stringify({ dark: true }))
const raw = await cs.getItem('settings')          // 没有返回 null
const many = await cs.getItems(['a', 'b'])        // { a: '…', b: null }
const keys = await cs.getKeys({ prefix: 'n:' })   // 自动翻页
await cs.removeItems(['a', 'b'])
```

## 并发

同一个用户可能在两台设备上同时改同一个键。`setItem` 带 `ifRev` 就是乐观锁:

```js
const { value, rev } = (await cs.getItemsWithRev(['n:1']))['n:1'] ?? { value: null, rev: 0 }
try {
  await cs.setItem('n:1', next, { ifRev: rev })   // rev 为 0 表示「这个键必须还不存在」
} catch (e) {
  if (e.code === 4007) {
    // 别的设备先改了:取回服务器的版本,和你的合并
  }
}
```

记事本的做法值得抄:冲突时两边文本一样就收下服务器的;不一样就**两份都留** —— 服务器那份不动,
本机那份另存为「(冲突副本)原标题」,永远不丢字。见[示例导读 · 记事本](examples.md#记事本的对账)。

## 离线

云存储要联网。离线优先的应用在本机(localStorage / IndexedDB)存一份缓存,联网后对账,记事本就是这么做的。
**本机缓存按 open_id 分开存** —— 同一台设备换了账号,不该看到上一个人的数据。

## 数据删除

- 用户在「我的 → 设置 → 小程序授权与数据」里能看每个应用的用量、导出 JSON、清空、移除;
- 用户注销账号时,他在所有小程序里的云存储一并删除;
- 你的应用被永久移除后,用户数据保留 **30 天**供导出,然后清除(这一条写进了开发者协议);
- 平台管理员在技术上能访问数据库,云存储**没有端到端加密** —— 敏感内容请自己加密或存在你自己的后端,并在隐私政策里写清楚。
