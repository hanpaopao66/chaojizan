# 示例导读

官方小程序和小游戏的源码都在开源仓 `miniapps/` 下(记事本、2048、贪吃蛇、方块消除、扫雷、五子棋、萌兽三路;后五个游戏共用 `miniapps/shared` 里的存档、随机数和界面零件),也是这份文档的参考实现。它们和第三方走**完全一样**的路:
同一个 SDK、同一个校验器、同一套审核记录(官方应用的审核人是平台管理员,记录里标「官方应用」)。

构建和打包:

```bash
bash scripts/build_miniapp.sh notepad   # → miniapps/notepad/dist/notepad.zip,打印 SHA-256
bash scripts/build_miniapp.sh 2048
```

zip 是**可复现**的(条目排序、固定时间戳、固定权限):同样的源码永远打出同样的 SHA-256,
和详情页公示的对得上 —— 你可以自己构建一遍来核对平台上跑的是不是这份代码。

## 记事本(`miniapps/notepad/`)

| 文件 | 干什么 |
|---|---|
| `src/notes.ts` | 纯函数:数据形状、首行即标题、时间文案、排序、搜索高亮、2 万字上限 |
| `src/sync.ts` | 离线优先 + 云存储对账(`NoteStore`),测试里换成假的存储 |
| `src/main.ts` | 界面:列表、编辑、回收站、关于 |
| `test/*.test.ts` | 纯函数和对账的单测(冲突、离线、别处删除、分批) |

### 数据形状

每条笔记一个键 `n:<id>`,值是 JSON:`{"v":1,"id","text","pinned","created_at","updated_at","deleted_at"}`。
id 是毫秒时间戳的 36 进制 + 4 位随机,按时间可排序。删除先进回收站(`deleted_at`),30 天后彻底删除。

### 记事本的对账

打开时先读本机缓存秒开,再 `getKeys('n:')` + `getItemsWithRev`(每批 100)对账:

- 服务器有、本机没有 → 收下;
- 本机没改过、服务器版本号变了 → 收下服务器的;
- 本机改过、服务器版本号也变了 → **冲突**:两边文本一样就收下;不一样就服务器那份不动,
  本机那份另存为「(冲突副本)原标题」—— 永远不丢字;
- 服务器没有了(别的设备彻底删了)、本机没改过 → 本机也删;本机改过 → 当新笔记存回去。

写入一律带 `ifRev`;`4007` 时取回服务器版本走上面的冲突逻辑。整个对账在 `sync.ts` 里,没有一行界面代码,
所以测试能直接跑两台「设备」同时改同一条。

### 几个值得抄的做法

- **主按钮和返回键交给宿主**:列表页 `MainButton.setText('新建笔记').show()`,编辑页 `BackButton.show()`;
- **有没同步的改动就开关闭确认**,同步完就关(`enableClosingConfirmation` / `disableClosingConfirmation`);
- **本机缓存按 open_id 分开**:键是 `notepad:v1:<open_id>`,换账号看不到上一个人的笔记;
- **后台同步不打断输入**:同步完成只刷新列表,不重建搜索框,光标不会丢;
- 用户写的字一律用 `textContent` 放进页面,不拼 HTML;
- 「关于」页如实写:数据存在超级赞云存储、官方也不能从服务端读、平台管理员技术上能访问数据库、没有端到端加密。

## 2048(`miniapps/2048/`)

| 文件 | 干什么 |
|---|---|
| `src/engine.ts` | 引擎,纯函数:滑动合并、出块、判定、带种子的 PRNG、存档 |
| `src/palette.ts` | 方块色阶(骨白 → 黏土 → 墨),每一档对比度 ≥ 4.5:1 |
| `src/main.ts` | DOM 方块 + CSS transform、输入、动画、存档、宿主能力 |
| `test/engine.test.ts` | `[2,2,2,2]→[4,4,0,0]`、`[4,4,8,8]→[8,16,0,0]`、每块每步最多合并一次、只在空格出块、无路可走、种子可复现、对比度 |

### 引擎

`move(state, dir)` 返回新状态和这一步的**过程**:谁滑到了哪、哪两块被合并掉(滑到哪)、合出了什么、新出了哪块。
界面据此先让所有块滑过去(120ms),再删掉被合并的、放上合出来的(弹一下)和新出的(从 0.6 放大)。
随机数是 mulberry32,**状态里存的是 PRNG 的当前状态**,所以存档恢复后接着出的块和没关过一样。

### 输入

滑动阈值 24px,一个方向要明显大于另一个(1.3 倍)才算,斜着划不算;键盘方向键和 WASD。
动画期间最多缓存 1 步输入,多按的丢掉 —— 不然连按几下会「积压」出一串意外的移动。

### 宿主能力

打开时 `requestFullscreen()`、`lockOrientation()`;合出 ≥ 128 时轻触感、拼出 2048 成功触感、没路走了警告触感;
设置键(`SettingsButton`)打开「关于」。

### 诚实的边界

没有广告、没有内购、没有排行榜。「关于」里写着:前端游戏的分数没法由服务器验证,成绩只存在你自己这里。

## 萌兽三路(`miniapps/critters/`)

三路卡牌塔防,五章 25 关加每日挑战。存档是这批游戏里最复杂的,值得看的是存档怎么设计,不是画面。

| 文件 | 干什么 |
|---|---|
| `src/battle.ts` | 对局模拟,纯函数:`newBattle(配置)` 建局,`step(局面, 指令)` 走一帧;不碰 DOM、不读时钟,同一个种子和同一串指令,结果一模一样 |
| `src/ai.ts` | 电脑出牌,也是纯函数 |
| `src/progress.ts` | 档案:星数、卡牌等级、卡组、成就;版本号、迁移表、两台设备的合并 |
| `src/data.ts` | 卡牌、关卡、成就、奖励表(全是数据,改数值不用碰逻辑) |
| `ASSETS.md` | 13 个 Kenney CC0 素材包的出处和许可证原文 |

### 两个云存储键

`best` 放档案(玩到头 2–3 KB),`state` 放打到一半的那一局(场面最满时约 40 KB,单个值上限 64 KB)。
分开放是因为两者的节奏不一样:档案只在结算、升级、换卡组时写;半局要随时能写,关掉回来接着打。

### 版本号和迁移表

档案带 `v`(`PROFILE_V`),读的时候按 `MIGRATIONS[n]` 一步步升到当前版本。
**新版本写的档案,旧代码只读、不覆盖**(`isFuture`):用户在新版本里玩过、又打开了缓存的旧版本,不能把新数据冲掉。

### 金币不存余额

`coins(档案)` 按账推出来:通关 + 星 + 成就 + 各设备自己挣的 − 升级花掉的。
存余额的话,两台设备各自改了余额,合并时只能二选一,不是多算就是丢;按账推,`mergeProfile` 取两边的并集就对。
唯一的边角:两台都离线、各自把钱花光,合并后可能是负数,游戏里照实显示。

### 每日挑战

按北京时间的日期定种子,人人同一关、两边卡牌固定 4 级。对局是纯函数,所以「同一关」是真的同一关,单测也能复现。

## 最小模板(`miniapps/_template/`)

三个文件,不用构建:同源引 SDK、展示 open_id、主按钮把 initData 交给你的后端验签。见[快速开始](quickstart.md)。
