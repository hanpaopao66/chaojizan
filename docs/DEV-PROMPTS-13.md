# 开发提示词 #132–#134:把「超级聚合平台」做进设计系统

承接 docs/DEV-PROMPTS-12.md。这一批不加业务功能,只解决一件事:
**现在的视觉系统是按「一个外卖 App」设计的,而你要做的是一个频道开放的聚合平台。**

## 判断依据(实地核查 + 横向对照)

对照了 VoltAgent/awesome-design-md 里 73 份品牌设计规格,重点看了结构最接近的
Uber(三端多边市场)、Airbnb(信任驱动交易市场)、Stripe(把透明做成品牌)。

**结论:一个都不采用。** 那些是品牌模仿套件 —— 对一个立身之本是
「我不是他们」的平台,穿上最像的那件外衣,第一眼就被归类成"又一个"。
Uber 的规格甚至写死 `#000000` 是唯一转化色、禁止第二强调色,照做就得先扔掉黏土橘。

而现有系统本身**已经是那份 Claude 规格的独立复刻**,且是 73 份里最贴合定位的一个:

| | Claude 规格 | 本项目 |
|---|---|---|
| 底色 | `#faf9f5` 暖奶油 | `#F0EEE6` 骨白 |
| 强调 | `#cc785c` 珊瑚 | `#C15F3C` 黏土橘 |
| 显示字 | 板衬线 Copernicus/Tiempos | Literata(同 Plantin 谱系,OFL) |
| 正文 | Styrene B | Space Grotesk(OFL) |
| 转化纪律 | 一屏一个实底 CTA | `brand.dart` 第 6 行已写明 |

Uber 那份最值钱的一条("One black pill per viewport is the whole conversion story")
本项目已经内化,不用学。

**真正缺的不是美学,是聚合平台的结构。** 实测:`碗/宿/券` 三个频道入口
共用 `sz.clay`,频道内页也没有任何标识 —— 用户从外卖进了住宿,
除了内容变了,**没有任何信号告诉他换了一个世界**。

### 132. 频道设计系统(开放集合,不是三个硬编码的颜色)

```
把「频道」变成设计系统里的一等概念,让新频道**加一行注册即可**,不改任何组件。

先读 docs/BRAND.md 与 packages/shared/lib/src/brand.dart。

现状:
- 首页金刚区三个入口(碗/宿/券)全部 `color: sz.clay`,视觉完全相同;
- 各频道内页(CategoryPage / HotelListPage / 团购)没有频道标识;
- 全仓搜不到任何 channelColor / stayAccent 之类 —— 零差异化。

**这条最容易做错的地方**:直接写三个常量 `外卖=橘 / 住宿=绿 / 团购=琥珀`。
那样第四个频道(打车)来的时候要改色板、改金刚区、改每个内页,
第五个再来一遍 —— 三次之后就没人愿意加频道了。**频道是开放集合,按开放集合设计。**

业务规则(已拍板):

1. **平台色与频道色分离,这是整条的地基。**
   `clay` 黏土橘从此是**平台色**:平台身份、承诺条、跨频道的主 CTA
   (支付/确认下单/提交)。**它不再属于外卖。**
   理由:如果外卖独占品牌色,后进的每个频道在视觉上都是二等公民 ——
   而聚合平台的前提是各频道地位平等。外卖和别人一样,领一个自己的频道色。

2. **频道色取自受限色板,不许自由取色。**
   预置 6–8 个低饱和暖色槽位(与骨白+黏土同一调性),新频道按顺序领用。
   不给自由取色是有意的:聚合平台变成彩虹糖就是从"这个频道想要个亮蓝"开始的。
   槽位用尽再讨论扩板,那时至少是一次有意识的决定。

3. **频道色的出现位置是白名单,不是随便用:**
   - 金刚区/频道入口卡的字符与细节;
   - 频道内页头部的标识条(细,不喧宾夺主);
   - 频道归属 chip(如订单卡上标"住宿");
   - 该频道的空状态插画着色。
   **禁止**用于实底主 CTA —— 那是平台色的位置,一屏一个实底按钮的纪律不能破。
   **禁止**用于金额、状态色(那是 earn/hold/warn 的语义位)。

4. **深浅色双态**:每个频道色必须给出深色态取值,不许只做浅色。

5. 频道注册表是**唯一事实来源**:key、中文名、字符、色槽、路由。
   金刚区从注册表渲染,不再手写三段 liveEntry。

技术要点:
- `packages/shared/lib/src/channels.dart`:`SzChannel` 与 `kChannels` 注册表;
  `channelOf(key)` 取不到时**回退到平台色**而不是抛异常 ——
  服务端将来返回一个客户端还不认识的新频道时,页面要能正常显示。
- 色槽定义进 `SzColors`(ThemeExtension),跟随深浅色;不要在 channels.dart
  里硬编码 Color 常量 —— 那样深色态会失效。
- `biz_type`(food/hotel)与频道 key 的映射放注册表里,不散落在页面。

验收:
- 金刚区三格颜色各不相同且都不是平台色;
- 三个频道内页各有自己的标识;
- **新增一个频道只改 channels.dart 一处**(用一个假频道验证,验完删掉);
- 一屏仍然只有一个实底 CTA(频道色不产生第二个);
- 深色模式下三个频道色都可读(对比度实测);
- 未知频道 key 回退到平台色不崩。
```

### 133. 「钱去哪了」的专属表面(排队,本轮不做)

```
账目透明是唯一抄不走的差异点,现在却和普通卡片长得一样。

Stripe 的做法可借:把数据/账目面板做成**深色表面**,从浅底页面里"硬"地凸出来。
本项目 SzColors 已有深色态取值,账本页、分账条、透明中心可以共用这个手法 ——
让"可查账"在视觉上就是一个独立、更硬的东西,而不是又一张卡片。

顺带:`szMoney()` 用 tnum 表格数字这件事,Stripe 规格里明确写着
("tabular caption sizes where money and numerics matter use tnum") —— 已做对,保持。
```

### 134. 三端密度分化(排队,本轮不做)

```
商家在忙碌的收银台前扫一眼、骑手戴手套单手操作、用户是躺着刷 ——
三种使用姿势,现在共用一套 `kPagePad=18 / kCardPad=14`。

商家端/骑手端需要更大的点击区与更低的信息密度;用户端可以更密、更"可逛"。
这不是抄谁,是本项目自己该定的规格,定完写进 BRAND.md。
```

---

## 明确不做的

- 不采用渐变网格 / 玻璃拟态 / 大量动效。产品说的是「账目透明、不玩花活」,
  界面越克制这句话越可信 —— **视觉克制本身就是论据**。
- 不引入高饱和促销色系(美团黄/饿了么蓝/抖音红那一挂)。
  在中国外卖语境里那是"促销"的信号,不是"可靠"的信号。
