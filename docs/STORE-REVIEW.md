## 零、单门店版(ICP / EDI 证下来之前提审用这一版)

### 0.1 为什么

增值电信业务的两张证(ICP 经营许可证、EDI 在线数据处理与交易处理业务许可证)还没下来。
商店审核的意见是:**改成单门店就可以上** —— App 只是一家店自己的点餐,不撮合多个商家、不招骑手、
不做聊天视频论坛小程序这类信息服务。

单门店版是**编译期**的另一个形态(`--dart-define=SUPERZ_EDITION=single`,
说明在 `packages/shared/lib/src/edition.dart`):下面「藏掉的功能」在商店包里**根本不编进去**,
不是靠后台开关藏。过审之后用后台开关把平台功能拨出来属于审核后变更功能,会被下架 ——
单门店版也拨不出来。拿到证之后,提审完整版的商店包(`USER_STORE_EDITION=full scripts/release_apks.sh …`)。

官网直链包、网页版、电脑版、商家端、骑手端都不受影响。商店包和官网包包名、签名相同,
官网包可以覆盖安装商店包(反过来也一样),这一点商店一般不管;**但没有 EDI 运营多商户平台的合规风险
在官网包上一样存在,不只是商店审核的问题**,这件事由运营方定。

### 0.2 单门店版里有什么

底栏三格:**点餐 / 订单 / 我的**。点餐那一格就是后台指定的那家店的点菜页。

| 保留 | 在哪 |
|---|---|
| 看菜单、菜品详情、加购、结算、外卖配送 / 到店自取、在线支付 | 点餐 |
| 店铺券领取与使用、评价、门店信息与证照公示、明厨亮灶标识、堂食标识 | 点餐(「评价」「商家」页签) |
| 订单列表(只列这一家店的单)、订单详情、催单、加菜、改地址、取消、售后、食安投诉、评价、再来一单、联系门店(电话) | 订单 |
| 优惠券、收货地址、帮助中心(单门店版自己的问答)、意见反馈、我的食安投诉、开发票(联系客服)、长辈版、协议与隐私 | 我的 |
| 订单通知开关、清除缓存、协议、关于我们、退出登录、注销账号 | 我的 → 设置 |
| 联系客服(工单) | 我的 → 右上角 |

**藏掉的**(全部编译期去掉):附近商家列表、金刚区(住宿、团购、买菜、帮我送、音乐、论坛、占位格)、
跨店搜索、分类页、城市切换和演示城市、视频、聊天(私聊、群、频道、订单群、通话)、论坛、音乐、
小程序和小游戏(含 `chaojizan.cc/m/` 直达链接)、机器人、AI 机器人、AI 助手令牌、扫一扫与扫码登录、
名片码、系统分享接收(不出现在系统分享面板里)、首页「+」菜单、超级赞号与勋章、信用分、实名认证、
拼单、分享卡与晒单、收藏、到店排队、团购券、住宿单、「我的」页按频道分的业务板块(只留一张「点餐」卡)、
透明中心、平台账本、「钱去哪了」分账、5% 承诺、小费与加急小费、开屏运营位、应用内更新。

### 0.3 上线前要做的(按顺序)

1. **服务端先上线**。单门店版依赖这一批服务端改动:`/config` 下发 `single_store`、
   `/orders` 和 `/orders/counts` 的 `merchant_id` 过滤、`/legal/store-terms`、`/legal/store-privacy`。
   服务端没更新的话,商店包打开就是「门店信息加载失败」。没有新迁移。
2. **后台「平台开关」→「单门店版显示的店」填商家 id**(`single_store_merchant_id`)。
   只收审核通过的外卖店;没填的话商店包首页显示「门店信息加载失败」。
3. **这家店要是真的**:营业执照、食品经营许可证上传并审核通过(「商家」页签的证照公示),
   菜品有实拍图和真实价格,营业时间、配送范围配好;建议打开「商家自配送」(单门店版没有平台骑手)。
   **不能拿 `demo_seed` 的演示店顶上去** —— 商店会核对证照主体。
4. 审核测试账号在这家店预置 1–2 笔历史订单和一个配送范围内的地址;`SMS_REVIEW_ACCOUNTS` 逐位核对(第二节)。
5. 打包:`make store-user VERSION=x.y.z BUILD=n`(产物 `build/store-apks/chaojizan-user-single-store-…apk`)。
   脚本打完会核对最终 APK:没有应用内安装、相机、麦克风、蓝牙、通讯录、后台定位权限,不认领小程序直达链接,
   不接收系统分享,是正式签名(和 App 备案登记的证书指纹一致)。
   build 号照旧严格递增。

### 0.6 核心体验路径(单门店版)

1. 首次启动:隐私弹窗(门店点餐版协议、隐私政策可看全文)→ 同意;
2. 游客浏览:点餐页看菜单 → 菜品详情 → 「评价」「商家」页签(证照公示);
3. 加购 → 去结算 → 触发登录(「登录 / 新用户注册」)→ 用测试账号登录;
4. 结算:外卖配送(选地址)或到店自取 → 提交 → 模拟支付 → 订单详情;
5. 订单:进度、联系门店、售后、食安投诉、评价;
6. 我的:优惠券、收货地址、帮助中心、意见反馈、协议;右上角联系客服、设置;
7. 设置 → 关于我们(运营主体、电话、邮箱、备案号)→ 注销账号(后果说明 → 勾选 → 倒计时确认)。

## 四、权限与隐私速查(审核员常问)

| 权限 | 申请时机 | 用途 |
|---|---|---|
| 位置 | 进首页附近商家/选收货地址/聊天里发位置时;骑手端上线期间持续获取 | 展示附近商家、算配送费;骑手端抢单排序与配送轨迹;拒绝则展示演示区域 |
| 相册 | 更换头像/上传凭证/聊天发图/投稿时 | 选取图片、视频上传 |
| 写入相册(用户端,iOS「添加照片」) | 保存聊天图片视频、分享卡「存图」时 | 保存到相册;Android 10 起不需要 |
| 相机(三端) | 用户端:聊天拍照拍视频、视频通话、「扫一扫」扫网页版 / 电脑版的登录码和别人的名片码;商家端:扫码核销、拍证照;骑手端:拍凭证 | 拍摄并上传;扫码只在手机上识别 |
| 麦克风(用户端) | 聊天按住说话、语音 / 视频通话时 | 录语音消息、通话 |
| 通知 | 首次进入订单场景 | 订单状态提醒 |
| 蓝牙(商家端) | 连接小票打印机时 | 打印订单小票 |

- 所有权限均"先应用内说明目的、用户同意后再调系统弹窗",拒绝不影响其他功能;
- 内嵌的第三方 SDK:三端都有的两个 —— 极光推送(JPush)、腾讯地图 SDK(2026-07-31 起地图改用腾讯官方 Flutter SDK),
  都在同意隐私政策后才初始化;用户端、商家端的 Android 版还有扫码用的 Google ML Kit 条码扫描(mobile_scanner 默认打包的
  `com.google.mlkit:barcode-scanning`,识别在手机上做,但会把机型、版本、安装标识等使用统计发给 Google;iOS 版扫码用系统 Vision,不含)。
  用户端用它「扫一扫」扫网页版、电脑版的登录码和别人的名片码(2026-09-14 起),商家端用它扫码核销团购券。
  三个都已在隐私政策第二节公示(含主体/信息/目的/链接;2026-09-13 起补上腾讯地图 SDK 和 ML Kit,2026-09-14 补上用户端的扫一扫);
- 微信支付为服务端接口方式,App 未内嵌支付 SDK;审核期间支付走模拟支付,
