# 官方精品小游戏:方块原野 / 星火牌局 / 突击时刻

平台已有的官方小程序是**轻量**的:记事本、2048、贪吃蛇、方块消除、扫雷、五子棋、萌兽三路。
这一批做三个更重的**原创单机游戏**,把「小程序里的游戏能做到什么程度」立成三个参考实现,
也给第三方开发者看三种不同的技术路线。

**选的是品类,不是作品。** 三个游戏分别对标「体素沙盒 / 回合制卡牌对战 / 战术射击」这三个品类,
但名称、规则、数值、地图、卡牌、美术、音效全部原创;没有使用任何商业游戏的商标、素材、角色或界面,
源码与「关于」页里也不出现商业游戏的名字(见每款的 `ASSETS.md` 与 listing 的原创性说明)。

三款都遵守平台既有边界:**免费、无内购、无广告、无排行榜、单机、不申请敏感能力**;
数据只存超级赞云存储(隐私政策逐款写清),美术全部程序化生成或内联 SVG,CSP 里没有外部请求。

> **上架状态(2026-10-18):三款都已构建、测试、浏览器验收完成,但尚未上架。**
> 小游戏版号/防沉迷的结论还没回来(见 [MINIAPP-COMPLIANCE.md](MINIAPP-COMPLIANCE.md) 第 7 条),
> 「再上新游戏同样先问运营方」——是否上架等运营方拍板。上线步骤见文末。

三款的共同实现约定:

- 原生 TypeScript + Vite,无框架、无运行时依赖;构建走 `miniapps/vite.config.ts` 的 `--mode <app>`;
- **纯逻辑与界面分开**:世界生成、碰撞、光线、规则、AI、存档序列化都是不碰 DOM 的纯函数,
  由 `test/*.test.ts` 用 `node:test` 直接测(不引测试框架);
- 存档走 `miniapps/shared/src/save.ts` 的 `SaveSlot`(本机秒开 + 云存储,按 open_id 隔离);
- 主题走 `miniapps/shared/src/base.css` 的宿主 CSS 变量 + `followTheme()`,亮暗两套;
- 尊重 `prefers-reduced-motion`;关键状态用 `aria-live` 播报;按钮都是真 `<button>`;
- 切后台暂停并立刻存档(`hostGame`),开始游戏时请求全屏并按 `superz.json` 锁方向。

## 方块原野(`miniapps/sandbox/`)

第一人称体素沙盒。程序化生成一座 128×128 的小岛(海面、沙滩、草原、石丘、树),用准星挖方块、
把挖到的方块放到别处,搭房子、搭桥、在山上开洞;九种方块、约八分钟一轮的昼夜。没有怪物、
没有合成、没有任务、没有联机 —— 就是一座岛。

- **渲染**:Canvas 2D 的 DDA 光线投射,程序化 16×16 方块纹理、距离雾、面的明暗、水面半透明;
  内部降分辨率渲染再放大保帧率。
- **交互**:挖(按住,不同方块硬度不同)/ 放(放到命中面的相邻格);热栏 9 格,数字键/滚轮/触屏切换;
  桌面上鼠标锁定 + WASD,手机上左下摇杆 + 右侧拖拽视角 + 挖/放/跳按钮。
- **存档**:种子、稀疏改动(上限 4000 格)、位置朝向、背包、世界时间、统计;序列化后远小于 64 KB。
- **代码地图**:`worldgen.ts` / `world.ts` / `raycast.ts` / `player.ts` / `inventory.ts` / `time.ts` /
  `save.ts` 是纯逻辑;`render.ts` / `textures.ts` / `icons.ts` / `hud.ts` / `menus.ts` / `input.ts` /
  `main.ts` 是界面与输入;`audio.ts` 是 WebAudio 合成。
- **单测**:世界生成确定性/地层不变量、编辑覆盖、DDA 命中、碰撞与滑动、放置面、背包、存档往返与坏档、
  编辑数量上限等。
- **诚实边界**:没有怪物、合成、多人、任务;成绩/世界只存在自己这里。

## 星火牌局(`miniapps/cards/`)

回合制卡牌对战,和电脑打。双方英雄 30 血,能量每回合上限 +1(最多 10),出随从站场、用法术解场,
把对面英雄打到 0。3 套各 30 张的原创预组卡组、36 张原创卡、两档 AI(标准 / 困难)。

- **规则**:抽牌/疲劳、手牌 10、场上 7、召唤失调、嘲讽、冲锋、圣盾、战吼、亡语、固定死亡结算顺序。
- **AI**:启发式评分 + 剪枝斩杀搜索;困难档会往后算斩杀、低血量更重视嘲讽保护;固定种子可复现。
- **界面**:竖屏;顶部敌方英雄/手牌/牌库,中间双方场面,底部手牌扇形 + 能量 + 结束回合;
  点选手牌出牌、点自己的随从再点敌方目标攻击;伤害飘字、攻击前冲、死亡淡出、圣盾破碎、回合横幅。
- **卡面**:全部内联 SVG + CSS 渐变程序化绘制;音效 WebAudio 合成。
- **存档**:整局状态(牌库/手牌/场面/能量/回合/种子)可续 + 战绩(场次/胜/连胜);坏档容错。
- **单测**:卡片数据自检、抽牌/疲劳/手牌上限、能量、召唤上限、攻击合法性(嘲讽/冲锋/失调)、圣盾、
  战吼/亡语顺序、法术与群伤、死亡与胜负、AI 走 N 步不产生非法状态且可复现、存档往返/坏档/≤64KB。
- **诚实边界**:单机 AI、固定预组、不能自建卡组;无英雄技能/护甲/武器;无多人、排行榜、内购、广告、开包抽卡。

## 突击时刻(`miniapps/tactical/`)

2D 俯视、回合制拆弹的战术射击。整张地图一屏可见:你是进攻方,75 秒内清掉或绕开 3 名 AI 守卫,
到 A 或 B 点按住 2.5 秒安放炸弹,再守住 30 秒;先赢 2 回合者获胜。

- **地图/物理**:44×26 格的 ASCII 地图(墙、掩体、A/B 点、出生点),圆 vs 格的滑动碰撞,DDA 视线;
  守卫只有在你视线内才画出来,失去视线留 1 秒「最后已知位置」。
- **战斗**:步枪 30 发弹匣、备弹 90、7 发/秒、换弹 2 秒、伤害 24;连射散布变大、停火恢复;
  瞬时 hitscan(先算墙再算人);没有爆头、护甲;命中表现是火花/弹壳/烟,无血腥表现。
- **AI**:3 名守卫,状态机「守点 → 听枪声调查 → 看见交火 → 炸弹安放后 1–2 秒内去拆」;
  BFS/A* 网格寻路;三档难度(**休闲/标准/困难**)只调反应时间、瞄准误差、视距、移动速度,
  玩家与守卫共用同一把枪,伤害/弹匣/射速三档完全一致。
- **流程**:冻结 2 秒 → 75 秒回合 → 安放 2.5 秒 → 炸弹 30 秒 → 拆弹 5 秒;三局两胜,结算有总击杀、
  安放次数、命中率、最佳连胜。
- **操作**:桌面上 WASD + 鼠标瞄准 + 左键开火 + R 换弹 + 按住 E 安放;手机横屏双摇杆(推右杆即开火)
  + 换弹/安放按钮。
- **存档**:战绩与设置(难度/声音);不保存进行中的比赛(回合制,回首页开新局)。
- **单测**:地图解析与可达性、碰撞滑动、LOS、hitscan(墙 vs 人)、BFS/A*、枪械弹匣/换弹/散布恢复、
  三档难度单调性(含固定种子 400 发命中率与「站着挨打」生存时长模拟)、AI 决策合法性与可复现、
  安放/爆炸/拆弹/回合状态机、存档往返与坏档。
- **诚实边界**:2D 俯视单机,不是 3D 射击;无多人、无开箱/饰品、无内购、无广告、无排行榜;
  不涉及真实武器品牌或真实地图。

## 工程接入与验收

三个应用接进 miniapps 共用构建体系(`miniapps/` 下):

```sh
cd miniapps
npm run typecheck:<app>           # 只查这个应用(+ shared / SDK)
npm run test:<app>                # 只跑这个应用的纯函数单测
npm run build:<app>               # vite 构建到 <app>/dist/pkg
bash ../scripts/build_miniapp.sh <app>   # 全量 tsc + 本应用单测 + 可复现 zip
```

`scripts/build_miniapp.sh` 现在只跑**目标应用**的单测:打包一个应用不该要求别的应用此刻也是绿的;
全量单测在 CI / `make analyze` 里跑(`node scripts/test.mjs` 不带参数)。测试脚本的输出目录带进程号,
并行开发时不会互相删缓存。

验收口径(每款都要过):

1. `npm run typecheck:<app>`、`npm run test:<app>`、`bash scripts/build_miniapp.sh <app>` 全绿;
2. 产物用 `server/app/services/miniapp_package.py:validate_package(zip, kind="game")` 校验通过,
   包内只有 `index.html`、`superz.json`、`assets/*.js`、`assets/*.css`,无图片/音频/字体/第三方库;
3. 无头 Chrome + `?sz_mock=1` 走一遍:首页 → 开局 → 操作 → 暂停/关于,亮暗主题、减少动态效果、
   竖屏/横屏两种视口都看;console 无 error、无外部请求、无内联脚本、无横向溢出、关键元素有 aria-live。
