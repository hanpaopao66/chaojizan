# 开发提示词 #277–#280:小程序,Telegram 模式

用户端要一个「首页下拉呼出小程序」的能力,交互对标微信,**实现对标 Telegram
Mini Apps**:小程序就是网页,跑在 WebView 里,能力靠一个 JS 桥给,
身份靠 HMAC 签名的 initData 传 —— 不自研渲染引擎,不引商业容器。

## 为什么是 Telegram 模式

- 微信那套(自有 DSL + 双线程渲染)是几百人团队的维护量,不是我们的仗;
- FinClip 这类兼容容器是闭源商业授权,和 AGPL 开源立场拧着;
- Telegram 刻意选了最普通的 Web 技术,让第三方零门槛 —— 这和我们
  「代码开源、账目可验」的路线是同一种选择:不造壁垒;
- 顺手还清一笔旧账:路线图里欠的「用户端 H5 版」,第一批自家小程序
  (透明中心、公开账本)就是它的起点,一份工两处用。

## 信任边界(先于功能定死)

1. **登录 token 永远不进 WebView。** 小程序页面拿到的身份是 initData:
   服务端把 `user_id、昵称(打码)、签发时间` 拼串,用平台密钥 HMAC-SHA256
   签名后下发;小程序的后端用同一密钥验签 + 校时间戳。第三方页面全程
   摸不到 JWT —— 这是 Telegram 最值得抄的一笔;
2. **桥只对清单内域名注入/应答。** 任意网页呼 `window.superz` 一律没有;
3. **支付不进小程序。** 桥只有 `openPayment(orderNo)`:回到原生支付链路,
   订单必须是自家后端创建的;小程序页面里没有任何输入卡号/密码的场景;
4. 权限类桥接口(定位、扫码)每次调用都弹原生确认,不做「一次授权永久有效」。

---

## #277 服务端:清单 + initData 签名

- 新表 `mini_apps`:name、icon、entry_url、allowed_origins(域名白名单)、
  perms(桥权限列表)、status(上架/下架)、sort;
- `GET /mini-apps`:登录态,只返回上架条目 —— 面板数据源;
- `POST /mini-apps/{id}/init-data`:登录态,返回
  `{payload: {...}, sign: hex}`;签名密钥从现有密钥体系派生
  (**独立派生,不直接用 JWT_SECRET 本体**),算法与字段序写进接口注释,
  将来第三方要照着验签;
- seed 两条自家条目:透明中心、公开账本(entry 指向官网对应页);
- 单测:签名算法定死(字段序、编码、时间戳窗口);e2e:登录 → 拉清单 →
  换 initData → 服务端自验签通过。

## #278 用户端:下拉呼出面板

- 首页滚动到顶继续下拉:overscroll 距离驱动面板跟手下移(不是触发动画),
  过阈值(约 90 逻辑像素)松手展开 + 中震;未过阈值回弹;
- 面板:小程序宫格(图标 + 名称),数据来自 `GET /mini-apps`,
  内容下滑或点空白收起;
- **与下拉刷新共存**是这条的验收重点:首页若已有 RefreshIndicator,
  两个手势必须分层清楚(方案:面板手势只认「刷新已结束且列表在顶」的
  二次下拉,或用拉距分段),做完真机上两个手势都要顺;
- 空清单时面板不可呼出(没有内容的抽屉比没有抽屉更糟)。

## #279 用户端:容器 + 桥

- `showModalBottomSheet` + WebView:半屏弹起,可拖到全屏,顶部带
  拖拽把手、标题、关闭;加载进度条;错误页给「重试/关闭」;
- 桥 `window.superz` 第一版五个:`ready()` / `close()` / `expand()` /
  `themeParams()`(亮暗主题色下发)/ `getInitData()`(异步,回 #277 的签名包);
- 域名白名单在**每次导航**校验(拦 redirect 逃逸),白名单外的链接
  甩给系统浏览器打开,不在容器内加载;
- WebView 插件选型:优先用仓库已有依赖;都没有则 webview_flutter
  (官方,MVP 够用),桥用 addJavaScriptChannel + runJavaScript。

## #280 验证

- `make unit`、`make analyze`(必须带 packages/shared);
- 本地起服务跑新增 e2e,查退出码;
- 真机/模拟器过一遍:下拉呼出 → 点透明中心 → 半屏拖全屏 → 关闭 →
  下拉刷新仍正常。

## 明确不做(这批的边界)

- **不自研小程序 DSL/渲染引擎**,不引 FinClip;
- **第三方入驻这批不做**:入驻要审核规则(对标商家入驻),规则没想清楚
  之前清单只有自家条目 —— 表结构留好 status 字段即可;
- **面板里不做推荐/排序算法**:sort 字段人工定,不做「猜你想用」;
  将来有第三方了也不做竞价位,这条现在就写下;
- 不做小程序间跳转、不做小程序分享卡片(等有真实需求);
- 商家端/骑手端这批不动 —— 先在用户端把模式跑通。

## 顺序

```
#277 服务端   ← 先定协议(initData 字段序一旦有第三方就改不动了)
#279 容器+桥  ← 吃 #277 的接口
#278 下拉面板 ← 纯交互,最后接上
#280 验证
```
