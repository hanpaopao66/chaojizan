# 开发提示词 #285–#292:地图能力的欠账

来源是两句话:「全面检查还有哪些端、哪些可以采用腾讯地图组件却没有用」
「继续深挖,腾讯地图服务端提供的能力咱们却没有用上的」。

调研分两半:**客户端该用组件没用的 3 处**、**服务端该调接口没调的 4 处**。
另加一条明确要去掉的降级(网格示意)。

---

## 0. 调研结论

### 客户端:三端都装了 `flutter_tencent_map`,真正用上的只有 4 个页面

| 用上了 | 页面 |
|---|---|
| 用户看骑手到哪了 | `delivery_map_page`(跑腿单同样生效,条件只看 riderId+状态) |
| 地址选点 | `MapPickerPage`(用户地址簿 / 商家入驻) |
| 商家自送配送 | `self_delivery_map_page` |
| 商家看骑手 / 骑手看配送 | `rider_track_page` / `map_page` |

### 服务端:腾讯 WebService 只调了 3 个接口

`place/v1/suggestion`(输入提示)、`geocoder/v1`(逆地理,两处)、
`direction/v1/bicycling`(骑行路径)。

## #285 连锁开新店在手输经纬度 —— 先做这条

`apps/merchant_app/lib/chain_page.dart` 的 `_NewShopPage` 有两个 `TextField`
让店主填「纬度」「经度」(`_lat` / `_lng`)。

而**同一个 App 的首次入驻**(`onboarding.dart:428 _pickShopSpot`)早就用了
`MapPickerPage` 地图选点,注释还写着「老板认自己店旁边那个地标,比认坐标容易」。
连锁总部开分店反而退回填数字。

**这不是体验问题,是数据正确性问题**:小数点后第 3 位差 1 就是 100 米,
第 2 位差 1 就是 1 公里。而这个坐标决定**用户能不能搜到这家店、骑手导航去哪**、
配送费按多远算。填错了没有任何一层会拦。

**要做**:

- 把两个坐标输入框换成 `MapPickerPage`(和入驻同一套调用,别另写);
- 地址栏保留,选点回来自动回填地址(`MapPickerPage` 的 `onReverse` 已经给了
  `name` / `district`);
- ⚠️ **不要只是把输入框设成只读**:老门店的存量坐标可能就是手输错的,
  改造后要能重新选一次。

## #286 骑手端「哪儿有单」把坐标当文字列

`apps/rider_app/lib/heatmap_page.dart` 拿到的是带 `lat/lng` 的网格数据
(含单量、样本量、`enough` 标记),渲染成:

```
34.3400, 108.9400
▓▓▓▓▓▓░░░░  12 单
```

骑手看不出这是哪儿。而这一页存在的理由就是「告诉他哪片单多」。
**给经纬度不算给信息,那是给数据。**

**要做**:用 `DeliveryMapView`(或直接 `TencentMap`)把格子画在地图上,
热度用颜色深浅。

⚠️ **这一页有一条既有红线不能碰**:热力图**只给「哪片单多」,不做
「推荐你去哪跑」**(DEV-PROMPTS-17:一旦变成指令就是变相调度)。
改成地图只是把同一份信息画对位置 —— **不许顺手加推荐路线、不许标
「建议前往」**。样本不足的格子照旧不画(`enough` 那个标记留着)。

## #287 酒店详情页没有位置

`apps/user_app/lib/hotel_detail_page.dart` 文件头写着「图集/设施/**位置**」,
实际只有一行地址文字(`:191`)。模型里有 `lat` / `lng`。

而同为到店业务的团购券有「到店导航」(`voucher_pages.dart:368`)、
外卖商家有「导航去店里」(`main.dart:4606`)—— 住宿反而没有。
**用户订了房找不到门。**

**要做**:详情页加一块小地图 + 「导航过去」按钮(复用 `navigateTo`,
它已经处理了高德/百度/腾讯的 scheme 和 BD-09 坐标转换)。

## ~~#288 ETA 接上腾讯给的 duration~~ —— 查错了,早就做完了

**这条作废,而且是我调研时的一个错误结论,留在这里当记录。**

我 grep 的是 `route_distance_and_duration`,库里没有,就下了「写好了没人调」
的判断。实际函数叫 **`bicycling_route()`**(`services/routing.py:89`),
而且链路是完整的:

```
payment_core.mark_order_paid → eta.compute_eta_async → routing.bicycling_route
                                      ↓ route_minutes
                             labor_guard.ride_minutes(取 max)
```

#268 那套口径一条不少地实现着:只取 `max(常量, 路网)` 所以只放宽不收紧、
路网时长超过常量 2 倍(`ROUTE_MINUTES_MAX_FACTOR`)就截断并记日志
(防坐标错导致「3 公里承诺 4 小时」)、拿不到就退回常量绝不编数,
还有 47 个单测覆盖。

**教训**:按函数名 grep 判断「有没有被调用」不可靠 —— 该按**调用链**查。
下次做同类调研,先找入口(谁在支付成功时算 ETA)再往下追。

## #289 抢单列表逐单调路径接口 → 改用距离矩阵

`routers/riders.py:1007` 在 **for 循环里**每单调 2 次 `bicycling_m()`
(骑手→商家、商家→用户),顺路判断还要再调 `detour_m()`。
一屏 20 单就是 40–60 次串行 HTTP,每次超时 3 秒。

Redis 缓存缓解了重复请求,但**缓存冷的时候正是午高峰第一批单**,
而那正是这个 App 存在的时刻。

腾讯有 `distance/v1/matrix`:一次算 N×M 组距离和时长(单次上限
20 起点 × 25 终点)。抢单页恰好是「1 个骑手 → N 家店」这种形态。

**要做**:加 `services/routing.py` 的批量函数,抢单列表改用它。

⚠️ 缓存键的口径要和现在的单点缓存**兼容**(`_key(a,b)` 那套),
否则矩阵回来的结果写不进旧缓存,单点调用又读不到 —— 两套缓存各热各的,
等于白做。

## #290 去掉「品牌网格示意」降级

`packages/shared/lib/src/delivery_map.dart` 在没有地图的情况下会画一张
网格 + 图钉的示意图(`_SchematicPainter` / `_SchematicPins` /
`_GridBackdrop` / `_GridPainter`,占了 398 行里的一大半)。**不要它了。**

⚠️ 但降级有**三种**触发原因,去掉的只是其中两种:

| 原因 | 判据 | 处理 |
|---|---|---|
| 没配地图 Key | `kTencentMapKey.isEmpty` | 去掉示意图。生产早就配了 key,这条路径实际不会走 |
| 没同意隐私政策 | 隐私门未过 | 去掉示意图 —— 那时本来就该引导他去同意,不是给张假图 |
| **平台不支持** | `!mapSdkSupported`(桌面 / Web) | **这条去不掉**,腾讯 SDK 在那些平台没有实现 |

**要做**:

- 三种情况都不再画网格,改成一块说明 + 「用外部地图打开」按钮
  (`navigateTo` 已经有了,它跳高德/百度/腾讯);
- 说明各写各的原因,别混成一句(现在那三句文案的区分是对的,留着):
  平台不支持是**永久**的,写「待启用」会让人一直等一个不会来的东西;
- 删掉那四个 painter/widget 类。

## #291 正向地理编码(配合 #285)

现在只用了逆向(坐标→地址),`geocoder/v1` 的正向(地址串→坐标)没用。
接上之后 #285 那个页面可以「填地址 → 自动出坐标 → 地图上确认」,
而不是只能在地图上找。

优先级低于 #285 本身:先把手输框换成地图选点,正向解析是锦上添花。

## 明确不做

- **IP 定位**(`location/v1/ip`):`witness/README` 那句「不收集、不上传
  关于你的任何信息」是全平台口径,定位只用系统权限给的那份。
  位置跟随方案(#281–284)里也写过同一条;
- **轨迹上报 / 电子围栏**:那是持续上传位置的能力,和骑手端
  「收工方向只存街道级、不进日志」的既有立场冲突;
- **行政区划接口**:`/geo/reverse` 现在已经能给结构化 `city`(#281 那批做的),
  不需要再引一个接口;
- **热力图上的推荐路线**:见 #286 的红线。

## 验收要一起看的

这批全是「有能力没用上」,所以每条都要过同一个问题:

**接上之后,少了哪一次人工输入 / 少了哪一次猜?**

- #285:店主不再输坐标 → 少一次填错的机会;
- #286:骑手不再对着经纬度猜是哪儿;
- #289:午高峰第一批单不再等 40 次串行请求。

答不上来的那条,就该重新想它值不值得做。
