先读 docs/DEV-PROMPTS.md 顶部通用约定(钱用分;流水 append-only;审计与 witness 恒等式必须绿;

## 本辑专属拍板(每条提示词默认遵守,不再重复问)

- **架构:平行竖井**,照团购券先例(独立表/独立 router/独立状态机),不抽公共订单层;
  但经营主体复用 Merchant——`Merchant.biz_type`('food' 默认/'hotel'),钱包/提现/分账/发票/税务白拿。
- **费率:住宿佣金 = 订单实付 5%,离店(核销)后才计佣**;取消/拒单/noshow 首晚均不计佣。
  config 加 `stay_commission_rate: float = 0.05`。对外一句话:"住宿 5%,离店才收,取消分文不收"。
- **金刚区定版:永远 8 格**:点外卖、住宿、超值团购、打车、家政、维修、货运、零工——
  **跑腿移除**,住宿放第 2 位。
- **取消政策三档**(房型级,下单时快照进订单):
  ①limited_free:入住日 X 点前免费取消(X 商家可配,默认 18:00),之后扣首晚;
  ②first_night:任何时候取消扣首晚(未支付订单除外);③strict:支付后不可退。
- **只做在线预付**(微信全额预付),到店付是 82 二期;不做信用卡担保、不做钟点房、不做竞价推广位。
- 新增文件命名统一用 **stay/stays**(订单域)与 **hotel**(商家资料域):routers/stays.py、e2e_stays*.py、
  hotel_profiles 表、apps/*/lib/hotel_*.dart / stay_*.dart。

### 67. 房型/房价/房态商家 API + 库存引擎(并发安全)

```
在 super-z 仓库开发「房型房价房态管理 API + 住宿库存引擎」。先读通用约定与本辑拍板。依赖 #66。

现状:#66 已有表结构,无接口;库存扣减/回补逻辑不存在。对标携程 eBooking 房态/房价模块。
业务规则(已拍板):
- 商家自助(/stays/me/*,require_role 商家):房型 CRUD(下架不删,历史订单引用);日历批量设置——按日期区间×房型批量改价/改总量/开关房,单日单改也走同一接口;查询返回「日历×房型」网格(未来 90 天);
- 总量下调不得低于该日已售 sold_qty(报中文错);过去日期只读;
- 库存引擎(services/stay_inventory.py):occupy(room_type, checkin, checkout, n) 对区间内每晚原子 UPDATE ... SET sold_qty=sold_qty+n WHERE closed=false AND sold_qty+n<=total_qty,影响行数≠晚数即整体回滚并报"X 月 X 日已满房";release 同理回补,幂等(靠订单状态判重,绝不能双倍回补);
- 任一晚 closed 或无日历记录 = 不可订。
技术要点:批量日历用 upsert(ON CONFLICT);occupy/release 必须在调用方事务内;写清注释:每晚一行是刻意设计(连住=多行同扣);网格查询接口带缓存但写后即失效。
验收:e2e_stays_inventory.py——并发 10 单抢 1 间只成 1 单(asyncio.gather 压测);连住区间中一晚满房则整单失败且已扣的晚全回滚;回补幂等(重复 release 不超卖恢复);总量下调低于已售被拒;关房当晚不可订。
```

### 69. 住宿下单 + 微信支付 + 三档取消退款全流程

```
在 super-z 仓库开发「住宿下单支付与取消退款」。先读通用约定与本辑拍板。依赖 #67。

现状:外卖支付在 routers/payments.py + services/wechat_pay.py;团购券自带独立支付路径与超时回补(routers/vouchers.py)——住宿照团购路径,不复用外卖 payment_core.mark_order_paid(含骑手语义)。
业务规则(已拍板):
- 下单 POST /stays/orders:校验日期(不早于今天、checkout>checkin、≤28晚)→事务内 occupy 库存+建单(created)+快照每晚价/取消政策→返回待支付单;15 分钟未支付自动关单回补(auto_flow 清扫,#70 兜底,支付回调时二次校验未关);
- 支付:微信 App 全额预付,复用 services/wechat_pay.py 下单与回调验签;回调成功→paid,推送商家新单;金额与订单不符拒绝入账记日志;
- 商家确认/拒单 POST /stays/me/orders/{no}/confirm|reject:拒单→全额原路退款,库存回补,不计佣;paid 后 2 小时未确认视为催办(推送商家,不自动拒);
- 用户取消 POST /stays/orders/{no}/cancel:按快照的取消政策算退款——limited_free 截止前全退;截止后/first_night 档=扣首晚(nightly_prices[0]×间数)退其余;strict=不退但可提"协商退"走售后(#80);扣的首晚给商家、**平台对扣款部分免佣**;取消即回补库存(strict 不退款也回补,商家可二次售卖——扣款+可复卖是行业惯例的商家保护,我们不加码);
- 退款一律走 wechat_pay.request_refund 原路退,退款单号入表。
技术要点:金额计算集中在一个纯函数(cancel_refund_cents(order, now))便于测试;所有资金动作过 audit 恒等式;取消/拒单的商家所得记入商家流水(离店前不计佣,见 #71 结算口径)。
验收:e2e_stays_order.py——下单→支付→确认→(#71 配合)全链路;e2e_stays_cancel.py——三档政策在截止前后各算对退款分;拒单全退;超时关单回补;strict 取消后同房可再售;审计绿。
```
