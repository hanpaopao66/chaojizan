# 开发者平台与 MCP(#38)

## 背景

平台要开源,需要一份能让外人接得上的开发者文档、一个开发者后台,
以及一套 MCP 工具,让 AI 助手能查数据、点单、看进度。

现状:
- `open/v1` 只有两个接口(`/shop`、`/orders`),**商家态、只读**,127 行;
- 没有任何开发者文档(`INTEGRATIONS.md` 讲的是外部服务联调,不是对外 API);
- API Key 的管理在 merchant-web 里,但没有用量、日志、配额。

**MCP 要的是"用户态"能力(找店、看菜、算价、下单、查进度),
和现有的"商家态只读"完全是两套东西** —— 不要试图在 open/v1 上加参数糊过去。

## 三个已经拍板的口径,照做,不要重新讨论

### 一、只做「商家集成」和「MCP」,不开第三方用户端

开源之后自然会有人想做替代客户端。**第一版明确不开这条**,并把理由写进文档:

第三方用户端需要一整套 OAuth + 用户授权 + 数据最小化,而它的收益
(别人做个更好看的 App)远小于风险 —— 一个钓鱼客户端拿走的是用户的
收货地址和手机号。等授权体系立住了再说。

### 二、MCP **不提供支付工具**,下单必须有一次人的确认

"点单"意味着一个 agent 能花用户的钱。这条线要划死:

- MCP **可以**做:查店、查菜、**算价**、创建待支付订单、查进度、查历史;
- MCP **不能**做:支付、改地址、退款、提现。

`create_pending_order` 返回待支付订单和一个确认入口,**人在自己 App 里
点确认才扣钱**。agent 干完 90% 的活(选店、比价、填地址、算总价),
而"花钱"这一下永远是人按的。

这不只是安全考虑,它和平台的整体立场一致:**判断权留给人,
平台和 agent 只负责把信息摆清楚。**

另外单独给 `quote_order`(算价不下单):agent 最常做的事是比价,
让它能算价而不产生垃圾订单。

### 三、沙箱这一版不做,但要把「不做的代价」写进文档

独立沙箱库要维护一套数据,生产库打标一旦漏判就是真钱。
两条都不便宜,而 MCP 因为没有支付工具,试用的风险已经被压到很低。

文档里必须写清楚:现在没有沙箱,开发者在生产环境试的话会产生
**真实的待支付订单**(不付款会在 15 分钟后自动关闭)。不写清楚就是坑人。

## 要做的东西

### 1. 开发者文档(`docs/API.md`)

FastAPI 自动生成的 OpenAPI **不是文档**。要手写的是自动生成不了的那部分:

- 认证:API Key 怎么拿、怎么轮换、泄露了怎么办;
- **错误码体系** —— 现在的错误码不成体系,这一步会逼出很多问题,
  先做它;
- 幂等:哪些接口有幂等键,重复调用会发生什么;
- 限流:规则和配额**公开写出来**,和公示派单算法一个路子;
- Webhook:事件列表、签名怎么验(给可运行的示例代码)、重投规则;
- MCP:怎么接、有哪些工具、为什么没有支付工具。

**每条业务口径链到透明中心那一页,不另抄一份。** 抄的那份迟早和真实
口径对不上,而那时候公开的是假的,比不公开更坏。这一条在
`services/dispatch.py` 的注释里已经写过一遍,同一个道理。

### 2. MCP 服务(`mcp-server/`)

- **stdio 传输**,不依赖第三方库。这是开源项目,少一个依赖少一份供应链风险,
  而一个最小 JSON-RPC stdio 实现只有几百行;
- 工具集:`search_merchants` / `get_menu` / `quote_order` /
  `create_pending_order` / `get_order_status` / `list_my_orders` /
  `get_transparency`;
- 每个工具的描述里要写清楚**它做不到什么**(尤其是"不能支付"),
  因为读描述的是模型,不是人。

### 3. 开发者后台

并进 merchant-web(那里已经有 API Key 页),补:

- 用量与配额:调用量、错误率、被限流次数;
- Webhook:订阅、重投、最近投递记录;
- 调用日志:方法、路径、状态码、耗时。
  **不记请求体** —— 里面有收货地址和手机号。

## 纪律

- **每个新接口配 e2e**;公平性/安全性的断言要**先弄红再修绿**,
  写完之后把守卫破坏一次,确认它真的会响 —— 不要写一个从不触发的守卫;
- 新增的用户态接口要过 `e2e_authz_regression` 那一关:
  换个身份调用必须被拒;
- 文档里出现的每个示例,要么有测试跑过,要么标明"未验证";
- 三端 analyze + Dart 单测 + 六项静态检查 + 安全扫描 + 全套 e2e 都要过
  (`make analyze` 现在已经包含 Dart 单测);
- **全程不要 push**。

## 完成的标志

1. `docs/API.md` 写完,错误码成体系,每条业务口径都链到透明中心;
2. MCP 服务能跑起来,七个工具都有测试,且**没有任何支付能力**;
3. 开发者后台三块(用量/Webhook/日志)可用,日志不含请求体;
4. 全套 e2e、单测、analyze、静态检查、安全扫描全绿;
5. 上面每条纪律都有对应的证据(哪条测试、怎么验的)。
