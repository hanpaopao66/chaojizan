# 决策记录索引

`DEV-PROMPTS-*.md` 是这个项目的决策记录:每批功能动手前先写清楚调研结论、
要守的边界、**明确不做什么以及为什么**,做完后把执行中的意外也记回去。
比 commit 信息更完整,适合想理解「为什么是这个设计」的人。

本索引只指路不复述 —— 每篇一行「讲了什么」加一条最值得看的决定,细节以原文为准。

## 从哪读起

第一次来,按需挑一篇:

- 想懂**这个平台为什么长这样** → [DEV-PROMPTS-4.md](DEV-PROMPTS-4.md) 的
  「大厂有但故意不做」清单,再看 [DEV-PROMPTS-13.md](DEV-PROMPTS-13.md)
  为什么 73 份大厂设计规格一个都不采用
- 想懂**账本和钱怎么做到可验证** → [DEV-PROMPTS-24.md](DEV-PROMPTS-24.md) +
  [TAX.md](TAX.md),协议规格在 [LEDGER-SPEC.md](LEDGER-SPEC.md)
- 想懂**骑手侧的立场**(全库重申次数最多的红线)→
  [DEV-PROMPTS-29.md](DEV-PROMPTS-29.md)(含一次公开的自我纠错)
- 想**部署一套** → [OPEN-A-CITY.md](OPEN-A-CITY.md)

两条贯穿全库的主线,散见于多篇:

1. **不做强制派单、不做骑手评分/段位/排名** —— 在 -2、-15、-16、-17、-21、-29
   反复重申,并被做成 e2e 扫描(周报返回体里出现排名字样直接红)
2. **5% 是上限不是目标,承诺类数字不可被运营配置覆盖** —— DEV-PROMPTS.md、-9、-10;
   公开账本把费率内嵌进每日 payload,见证节点核的是「实收 ≤ 承诺」
