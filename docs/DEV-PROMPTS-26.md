# 开发提示词 #212–#236:用户端鸿蒙版完全复刻

#207–#211 把主链路跑通了(隐私门 → 登录 → 首页 → 店铺 → 购物车 → 结算 →
支付 → 订单列表 → 订单详情),2889 行 ArkTS。这一份是**剩下的全部**。

对照的目标是 Flutter 用户端:`apps/user_app/lib` **15496 行**、
9 个页面类挤在 `main.dart` 里、30 个独立页面文件、调用 **84 个不同的接口**。
也就是说复刻完成时鸿蒙端的体量大致相当,现在走了不到两成。

## 先说清楚哪些不做,以及为什么

**这三类是"实在开发不了",不是偷懒:**

1. **应用内自更新**(安卓端的 `apk_installer`)。鸿蒙没有 APK 这个概念,
   而且华为应用市场和国内商店一样**明令禁止绕过审核的自升级** ——
   安卓端为此专门做了 store 渠道包把权限摘掉(#192)。鸿蒙端更新交给应用市场,
   连"检查更新"入口都不该有。
2. **未上线业务的愿景页**(`coming_soon_page.dart`)。安卓端用 feature flag
   关着(`kShowComingSoonBiz = false`),审核包里整体不渲染 —— 鸿蒙端不用建。
3. **开屏运营图**(`splash_gate.dart`)。它是安卓端隐私合规返工的起因
   (启动即请求 `/splash` 并下载图),鸿蒙端从一开始就没有它,别再引进来。

**下面这些代码要写,但没有外部凭据就联调不了**,写的时候必须留降级路径,
**在拿到凭据之前不许假装成功**:

| 能力 | 缺什么 | 没有它时的行为 |
|---|---|---|
| 微信支付 | OpenSDK 的 HAR 包 + appId | 明说"支付暂不可用",订单保留待支付 |
| 推送 | 华为 Push Kit(AppGallery Connect 配置)或极光鸿蒙 SDK | 不推,靠进 App 看;**不要静默失败还显示"已开启通知"** |
| 地图 | 腾讯鸿蒙地图 SDK + key | 地图位置降级成文字地址 + 距离 |
| 微信分享 | 微信 OpenSDK | 降级成系统分享/复制文案 |

## 批次 A · 点餐链路补完(#212–#216)

### #212 搜索

对照 `search_page.dart`(409 行)。要有:搜索历史(本地)、热词(服务端按真实销量)、
250ms 防抖联想、**搜菜品不只搜店**、结果内筛选排序。

⚠️ 安卓端的已知短板别抄过来:搜菜名时服务端只返回**店铺卡**,
用户还得进店自己翻。鸿蒙端做的时候把命中的菜名显示在店铺卡上
(接口已经知道是哪道菜命中的,只是没展示)。

距离档位用 `[不限, 1km, 2km, 3km]` —— **不要出现 5km**,
服务端已经把浏览半径收敛到配送上限,5km 是个骗人的选项。

### #213 品类页与列表筛选排序

对照 `category_page.dart` + `main.dart` 的筛选栏。品类清单**走接口不要硬编码**
(`GET /merchants/categories`),安卓端本地存了一份副本,改品类要发版。

筛选维度与搜索页保持同一套:距离、评分、起送价上限、只看有优惠。
排序:距离 / 评分 / 月售。**排序口径下面那句"没有竞价排名"要保留** ——
那不是装饰,是产品主张。

### #214 菜品规格与加料

对照 `main.dart` 的 `_pickOptions`。`Dish.options` 是 JSONB 的规格/加料组,
选项带加价。三条硬要求:

1. **价格以服务端为准**。下单接口会用 `resolve_options` 重算,
   客户端算出来只用于显示 —— 两边对不上时听服务端的;
2. **同菜不同规格算不同行**,不要合并份数;
3. **规格面板要校验库存**。安卓端这里有 bug:走规格路径时直接 `quantity++`,
   绕过了无规格路径的库存拦截。

顺带补安卓端**没有**的:**菜品级备注**(不要辣、不要香菜)。
中式外卖这是刚需,现在只能写在整单备注里靠商家自己拆。

### #215 地址簿

对照 `address_pages.dart`(702 行)。列表、新增、编辑、删除、设默认、
按距离排序、**智能识别**(粘贴一段"张三 138xxxx 某某小区3栋502"自动拆字段)、
地图选点(依赖地图 SDK,没有就降级成手填 + 定位取当前点)、城市切换。

楼层与电梯这两个字段**要收**:服务端按它算上门难度费,而且会让 ETA 诚实一点
(爬 6 楼确实更慢)。收的时候说清楚为什么问。

### #216 购物车持久化、我的常点、再来一单、加菜

- 云端购物车(`carts.py`):登录用户防抖上报、进店恢复。
  **游客的车只在内存里**,这是服务端的角色限制,不是 bug,但要在 UI 上让用户知道;
- 我的常点(`/orders/frequent`):近 90 天的"店+菜"组合,一键预填;
- 再来一单:仅 `completed` 单可见;**跑腿单不进这个列表** ——
  它的 merchantId 指向虚拟主体,点进去是空菜单,而且"再来一单"对跑腿本来就不成立;
- 加菜(`append_order_page.dart`):关联原单、免配送费、随原单配送。

## 批次 B · 订单后链路(#217–#220)

### #217 订单实时状态、时间轴、ETA、催单

WebSocket 走 `@kit.NetworkKit` 的 `webSocket`,连 `/ws/orders/{order_no}`,
**慢轮询兜底**(断线期间不至于卡住)。三条从安卓端搬过来的结论:

1. **到终态就停表**。已完成/已取消不会再变,继续轮询是白跑;
2. **退到后台停表**。用 `onForeground`/`onBackground` 或页面生命周期;
3. **ETA 只有一个来源**。安卓端一度同页两套 ETA(头部用服务端 `eta_at`、
   时间轴内自己重算),两个数字会打架。

催单、加急小费、改地址、确认收货都在详情页。超时会自动赔安抚券,
那条文案要显示出来 —— 平台赔了钱不说,等于没赔。

### #218 配送地图与联系骑手/商家

对照 `delivery_map_page.dart`。骑手位置轮询 5 秒 + 插值动画,**后台暂停**。
没有地图 SDK 时降级:显示"距你还有 X 米"和状态时间轴,不要留一块白板。

联系:IM(`/orders/{no}/messages`,3 秒轮询)+ 电话兜底。
**隐私号**:服务端 `privacy_phone` 未接时会下发真号,
客户端不要额外展示,拨号即可 —— 号码显示在界面上截图就泄露了。

**未读数**(`/orders/{no}/unread`)要在订单卡片和聊天入口显示红点。
安卓端漏了这个:骑手发消息用户完全不知道,沟通失败直接变差评。

### #219 售后与食安投诉

- 普通售后:申请、图片举证(必传)、退款逐笔进度、被驳回后申诉;
- **食安是红线通道**:不经商家直达平台,可附医疗凭证,标红加急;
- **投诉状态要能查**(`/food-safety/order/{no}` 和 `/food-safety/mine`)。
  安卓端一度只能提交查不到进度 —— 对一个把食安当卖点的平台,
  投诉黑洞比没有投诉入口更伤。

⚠️ 安卓端未解决的两个缺口,鸿蒙端**直接按正确的做**:
**部分退款**(勾菜品/填金额,现在只能整单发文字)、
**用户侧申请平台介入**(现在商家一驳回就只能发工单)。
这两条要服务端配合,做之前先确认接口。

### #220 评价

双评分(商家 + 骑手)、标签分离、图片最多 3 张、**真匿名**、追评、
商家回复与追评回复。**待评价列表**安卓端没有,鸿蒙端补上 ——
不提醒的话评价率会很低,而评价是新店唯一的信任来源。

## 批次 C · 账号、设置与合规(#221–#224)

### #221 「我的」补完

收藏(`favorites.py`,收藏即发商家券)、券包、地址簿入口、实名认证
(`identity_page.dart`,酒类订单需要)、发票(`invoices.py` 后端早就就绪,
安卓端一直挂着"待接入"的弹窗,鸿蒙端直接接)。

### #222 设置与账号注销

通知开关、清缓存、关于(版本号、ICP 备案号、平台主体)、
**账号注销**(《个人信息保护法》和应用商店强制项)。

注销要照搬安卓端的三步:后果说明 → 勾选确认 → 倒计时二次确认,
且服务端有在途订单/未提余额三道拦截。**不要做成一个按钮点了就没**。

**不要有"检查更新"入口**(见开头"不做"的第 1 条)。

### #223 证照公示与明厨亮灶

- 证照公示(`licenses_page.dart`):**餐饮商家要同时公示营业执照和食品经营许可证**,
  总局令第 123 号第十一条。图走服务端加水印的公开出口;
- 明厨亮灶直播:鸿蒙用 `@kit.MediaKit` 的 AVPlayer 播 HLS。
  拉不起来要**自动降级**并说明,不要黑屏转圈。
  标识本身在列表页和店铺页都要有,**有和无两种都标**(第十三条)。

### #224 消息中心、帮助、客服、反馈

消息中心(公告 + 订单动态,带未读)、帮助中心(FAQ 服务端下发 + 本地兜底)、
客服工单(`SupportPage`)、意见反馈。

⚠️ 反馈这个功能**全部意义在回复**。只存不回比没有更糟:
提过一次没人理,以后连提都懒得提。

## 批次 D · 平台叙事(#225–#227)

这一批是这个产品**区别于美团的唯一部分**,不是锦上添花。

### #225 透明中心原生页

对照 `transparency_page.dart`(1669 行,安卓端最大的单页)。
十个公开端点全部渲染:每日核账、资金去向、赔付记录、月度财报、公平性、
更新日志、可用率、明厨亮灶规则、治理留痕、派单算法。

**这一页的价值在于它敢难看**:核账差一分钱亮红灯、探针缺档按不可用算、
平台倒贴照实写。做的时候有两个坑安卓端踩过:

1. **服务端返回的是"有记录的天",不是日历天**。直接渲染会把"没查过"
   显示成"没问题" —— 要按 90 天日历补齐,缺的天单列;
2. `clean_streak_days` 只按运行记录连续数,**会高估**,旁边要标口径。

### #226 钱去哪了、5% 说明、信任页、见证节点

- 「钱去哪了」(`money_flow_page.dart`):每单分账实算;
- 5% 说明(`five_percent.dart`):静态说明弹层;
- 信任页(`trust_page.dart`):结论层,底部进透明中心;
- 见证节点(`/nodes/summary`):在线节点数、复算一致性、最新锚点。

### #227 分享卡与邀请

**晒单分账卡**是这个平台唯一落成的差异化传播物料:三色分账条
(商家 X / 骑手 Y 含配送费与小费全额 / 平台 Z),金额可打码。
鸿蒙用 `componentSnapshot` 截图组件成图。

邀请:6 位邀请码,**链接要带 code**(安卓端的链接不带,朋友得手输六位数,
转化全漏在这一步)。分享降级顺序:微信 SDK → 系统分享 → 复制文案。

## 批次 E · 另外三条业务线(#228–#230)

### #228 团购券

列表、详情(安卓端**没有详情页**,点卡片直接弹购买抽屉、确认即扣款 ——
鸿蒙端补上)、购买、券包、核销二维码与 12 位码、未核销全额退。

⚠️ 安卓端有一句**没有实现支撑的承诺**:券包页写着"过期前有提醒",
而全仓没有任何到期提醒任务。鸿蒙端要么别写这句,要么等服务端做了再写。

### #229 住宿

列表(关键词/日期/排序/档次)、详情(图集/设施/房型报价/取消政策三色/点评)、
下单、订单五节点时间线、**取消先试算再确认**、到店无房售后、评价与追评。

这条线安卓端闭环度最高(约 90%),接口也全,复刻主要是 UI 工作量。

### #230 跑腿

帮送 / 帮买两种。实时报价、费用明细单列 2% 服务费、禁运硬拦、
帮买加价协商、小票展示。

⚠️ **下单后必须直接进支付**。安卓端在这里出过最严重的一个洞:
订单建出来是待支付,而路由 push 完不管返回值,用户填完地址点了下单、
页面一关单子就没了,15 分钟后被自动清扫。

## 批次 F · 三方 SDK(#231–#234)

这四项**代码可以写完,但没有凭据验不了**。写的时候统一守一条:
**拿不到能力时诚实降级,不许假装成功。**

### #231 微信支付(鸿蒙 OpenSDK)

HAR 包放 `entry/libs/`,启动注册 appId,把 `common/Pay.ets` 里的 TODO 换掉。
**支付结果以服务端回调为准**,客户端返回值只做展示。

### #232 推送

鸿蒙 NEXT 的推送必须挂**华为 Push Kit** 作为厂商通道
(极光的鸿蒙 SDK 也是这么做的,要在 AppGallery Connect 配 AppId/AppSecret)。
要推的节点:商家接单、出餐、骑手取货、即将送达、已送达、退款、ETA 变更。

**点推送要能跳到对应订单**(深链)。安卓端漏了这个:
`addEventHandler` 都没挂,点了推送只是打开首页。

### #233 腾讯地图

地图选点、配送轨迹。没有 key 时全部降级成文字 + 距离。

### #234 微信分享

分享店铺卡、晒单分账卡。降级顺序见 #227。

## 批次 G · 体验、性能与上架(#235–#236)

### #235 深色模式、长辈版、无障碍

- 深浅两套色板跟随系统。现在 `color.json` 只有一套,要补 `dark` 限定目录;
- **长辈版大字**:安卓端是 1.4× 封顶。外卖用户里老年人不少,这不是可选项;
- **无障碍**:安卓端 `Semantics` 用了 **0 次**,是明确的欠账。
  鸿蒙端在关键交互(加购、下单、支付、订单状态)上补 `accessibilityText`,
  别再欠一遍。

### #236 上架合规

- 权限:用到时才申请、说明用途、**不申请用不到的**(相机就不要,
  所有图片选择走相册);
- 隐私政策里的第三方 SDK 清单要**照实列**(推送、地图、支付各是谁、收什么);
- 个人信息收集清单按场景列;
- 华为应用市场的审核政策另有资质要求,见下。

## 顺序建议

批次 A → B 是"能不能用"的问题,先做。
批次 D(平台叙事)看着像锦上添花,但它是这个产品**唯一不可替代的部分** ——
一个只会点餐的鸿蒙外卖 App 没有任何理由让用户装,建议提到 C 前面。
批次 E 的三条业务线可以最后,它们在安卓端也是逐批长出来的。
批次 F 卡在凭据上,拿到一个接一个。

## 最后提醒一次:卡点不是代码

华为激励 2026 报名截止 **9-25**、上架截止 **9-30**,新应用 3000 元,先到先得。
而**软著、App 备案(工信部)、华为开发者企业实名认证**三样都还没办,
华为应用市场审核要资质,软著正常流程一到两个月。

**这三件的优先级高于本文档里的任何一条。** 代码复刻完了证没下来,一样上不了架。
