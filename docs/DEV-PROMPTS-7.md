## 商店通用要求速查(整改时对照自检)

- **工信部/国内商店**:首启隐私弹窗(已有 `packages/shared/lib/src/privacy_gate.dart`,自检文案与链接可达);
  隐私政策内公示第三方 SDK 与权限用途;权限**先告知目的、后调系统弹窗**,拒绝不影响其他功能;
  权限最小化(Android 已做 `tools:node="remove"` 裁剪,保持);账号可注销;
  **App 备案**——域名 chaojizan.cc 已有陕ICP备2025064101号-5,需确认 App 备案号已办并在应用内"关于"页展示,国内商店现在是硬门槛。
- **苹果**:Guideline 2.1(提供演示账号)、4.2(最少功能量,防"垃圾软件")、
  5.1.1(注册入口、游客可浏览、权限用途字符串 `NS*UsageDescription` 缺失直接拒)、
  5.1.1(v)(App 内可发起注销账号)。
- **共同**:审核人员定位在外地/海外,任何"按定位展示"的页面必须有兜底内容,不能白屏空列表。

## 本辑专属拍板(默认遵守)

- **隐私政策仍是单页** `server/static/legal-privacy.html`(三端共用 `/legal/privacy`),
  SDK 公示与权限附录里按"三端通用 / 用户端 / 商家端 / 骑手端"分小节,不拆三份文件。
- **只公示真实接入的东西**:以 `apps/*/pubspec.yaml` + 三端原生工程(AndroidManifest / Info.plist /
  build.gradle / Podfile)盘点为准,没接的 SDK 一律不写(写了反而要解释)。纯 Flutter 插件
  (geolocator/image_picker 等)按"权限用途"公示,不算第三方数据 SDK;微信支付若是
  服务端 H5/JSAPI 拉起、App 内无 SDK,则如实按现状写。
- **权限申请统一封装**:shared 包新增 `requestWithRationale()`(先弹自定义中文说明
  → 用户点"去授权"才调系统弹窗 → 拒绝后引导去系统设置),三端所有权限调用都走它,
  不允许裸调 `Geolocator.requestPermission()` / `ImagePicker.pickImage()`。
- **游客模式只做用户端**;商家端/骑手端是 B 端工具 App,登录门禁保留,苹果侧用
  演示账号(#100)过审。
- **功能开关用编译期常量**(如 `lib/feature_flags.dart` 里 `const kShowRideHailing = false`),
  不做服务端下发——上架整改要的是"审核包里看不见",常量最稳;打车上线时改回来即可。
- **审核兜底数据用真库演示商家**,不做前端 mock:生产库里已有/补齐一批演示商家与
  商品(真实图片、合理价格),兜底逻辑是"附近为空 → 展示演示城市商家 + 顶部提示条",
  数据链路与真实用户完全一致,审核下单也能走通。
- **验收统一含**:改到的 Flutter 端 `flutter analyze` 零问题;改到 server 则本地起服务实测;
  完成后不 push。
